# 抖音短视频口播文案规范

> **抖音优先，生成口播前必读。** 本规范结合抖音创作者中心、巨量引擎、抖音电商学习中心等平台资料，以及短视频行业实践整理。
> “前3秒/前5秒”是运营分析窗口，不是抖音公开的统一流量阈值。真正要优化的是：用户是否停留、是否持续观看、是否完成内容承诺、是否产生真实互动。

## 1. 开头：前3秒抢注意，前5秒确认价值

### 目标

- **0-3秒**：让目标观众知道“这条和我有关”。
- **3-5秒**：说清楚视频解决什么问题、会给什么判断或结果。
- **5秒以后**：尽快兑现承诺，不要只吊胃口。

### 六种抖音开头

| 类型 | 公式 | 女性向情感示例 |
|---|---|---|
| 问题型 | 具体痛点 + 直接提问 | “为什么你越主动，他越躲？” |
| 结果型 | 结果 + 目标人群 | “总在感情里内耗的女生，先记住这句话。” |
| 反常识型 | 常见认知 + 反转 | “恋爱变平淡，不一定是不爱了。” |
| 站队型 | 身份 + 真话 | “我是男生，跟你说句不太好听的实话。” |
| 场景型 | 具体时刻 + 冲突 | “如果你正在经历分手后的反复联系，先别急着删掉这句话。” |
| 清单型 | 对象 + 数量/判断标准 | “判断一个男生是否认真，看这三个细节。” |

### 开头禁忌

- 不先寒暄、自我介绍、空镜或无信息动作。
- 不写“大家好，今天我们来聊一个很重要的话题”。
- 不用“全网没人告诉你”“看完一定后悔”等无证据夸张承诺。
- 钩子必须和正文一致，不能用虚假冲突骗停留。

## 2. 一句话吸引力

开场一句最好同时包含：

```text
目标人群 + 明确问题/结果 + 观看承诺
```

示例：

> “如果你总是替一个忽冷忽热的男生找理由，这条视频帮你看清问题到底在哪。”

好的第一句话应当：

- 具体，不说“今天聊个重要话题”；
- 指向明确人群，不对所有人泛泛而谈；
- 承诺可感知结果，不说空泛的“让你有所收获”；
- 后文能兑现，不把普通建议包装成“唯一真相”。

## 3. 正文结构

### 揭秘/避坑/清单式

```text
钩子
→ 先说判断
→ 第一/第二/第三个具体点
→ 每点：结论 → 生活场景 → 判断/提醒
→ 回扣核心观点
→ 一个具体 CTA
```

每个分点必须完成三步：

1. **抛结论**：先告诉观众发生了什么；
2. **给画面**：用动作、对话、时间和地点替代抽象形容词；
3. **落提醒**：告诉观众怎么判断、怎么处理或下一步做什么。

### 金句/观点式

```text
反常识观点
→ 解释为什么
→ 一个生活细节或真实场景
→ 另一层推导
→ 留一句能记住的结论
```

### 口播长句式

```text
生活小事/具体场景
→ 情绪或冲突
→ 抽象成关系规律
→ 回到观众自身
```

不要只吊胃口。悬念必须持续提供新信息、例子、转折或情绪推进。

## 4. 口播节奏

- 一句话只表达一个主要意思，关键观点前后留停顿。
- 多用短句、动词、具体名词，少堆抽象名词。
- 用“但是、所以、问题是、真正关键在于”制造自然转折。
- 每隔一段改变信息形态：观点 → 例子 → 反问 → 结论。
- 重复可以强调情绪，但不要机械复读同一结构。
- 删掉“然后呢、就是说、其实、大家知道”等无效气口；口播转写后运行 `enhance_transcript.py`。
- 设计师身份只自然带过，不强行使用图层、排版、改稿、用户体验等类比。

推荐脚本骨架：

```text
钩子 → 明确问题 → 解释原因 → 给出方法/案例 → 总结 → 轻量 CTA
```

拍摄前朗读检查：是否一口气过长、是否有书面句、是否同义重复、字幕是否能跟上语音。

## 5. 字幕和画面

- 字幕必须准确、同步、易读；不要整段文字一次铺满。
- 一屏突出一个信息点，数字、专名和结论可以视觉强调。
- 口播讲什么，画面就解释什么，不要口播讲 A、画面放 B。
- 提出问题时用人物表情/错误示范；讲步骤时用编号/动作；举例时用对话/前后对比；下结论时给大字结论。
- 字幕、贴纸不要遮挡人物脸部、关键画面或抖音底部操作区域。
- 使用他人素材、音乐、图片、聊天记录时确认授权；真人案例做匿名化或明确情景演绎。

## 6. 标题、话题与搜索承接

- 标题包含用户可能搜索的核心词、对象、问题或结果。
- 标题与口播、字幕、话题保持一致，不堆无关热词。
- 话题使用垂类、场景、人群和具体问题，不能用热门话题代替内容质量。
- 标题可采用：数字+结论、后果预警、反常识判断、对象+问题、场景+结果。

## 7. 评论 CTA

一次只设置一个主要动作，并且与内容相关：

- 评论型：“你遇到过哪一种？”
- 选择型：“A 还是 B？把答案打在评论区。”
- 实践型：“把你的开头发出来，我帮你看看。”
- 收藏型：“下次遇到这种情况，按这三个问题检查一遍。”
- 连续观看型：“下一条我拆一个真实案例。”

避免“点赞关注三连”、虚假福利、强制转发、恐吓诅咒、批量诱导评论和违规站外引流。

## 8. 情感赛道边界

允许做：关系沟通、冲突处理、情绪识别、边界感、自我保护、去标识化的个人经历复盘。

必须规避：

- 把个案说成“所有男生/女生都这样”；
- 给陌生人做心理诊断或确定性人格判断；
- 编造真实案例、公开聊天记录、照片、姓名和家庭信息；
- 色情擦边、暧昧引流、情感诈骗、保证复合/挽回；
- 鼓励报复、跟踪、偷拍、骚扰、网暴或自我伤害；
- 把家暴、创伤、抑郁等痛苦娱乐化；
- 以心理、法律、医疗专家身份给无资质的确定性结论；
- 制造男女对立、贩卖“再不恋爱就晚了”的焦虑。

安全表达：使用“可能”“常见情况”“如果反复发生”等限定；涉及危险关系时优先建议保护人身安全并寻求正规帮助。

## 9. 数据复盘

不要只看点赞。发布后重点看：

1. 0-3秒是否明显流失；
2. 3-5秒用户是否理解主题和收益；
3. 中段哪里出现重复、空泛或信息密度下降；
4. 结尾是否兑现承诺、CTA 是否突兀；
5. 评论区反复出现的问题能否转成下一条选题。

没有可靠依据证明“固定3秒”“固定完播率”“固定时长”必然爆。它们只能作为测试假设，最终以自身账号历史数据为准。

## 10. 生成前检查

- [ ] 开头是否同时点明对象、问题或结果？
- [ ] 标题/封面承诺是否会在正文兑现？
- [ ] 前半段是否持续提供新信息？
- [ ] 每个分点是否都有具体场景或动作？
- [ ] 是否有自然停顿、转折和句式变化？
- [ ] 是否避免绝对化、性别对立和未经证实的心理判断？
- [ ] CTA 是否只有一个主要动作？
- [ ] 是否通过 `prepublish_check.py` 总检？
